## 4. Existing Systems

- Traditional spam filters (rule-based, Bayesian)
- Binary ML classifiers (spam vs. ham)
- URL-only blacklist tools (PhishTank, OpenPhish) — limitations
- Why existing tools are insufficient for phishing detection

## 5. Proposed System

- Three-class ML classification: Legitimate / Spam / Phishing
- TF-IDF text features + 14 cybersecurity heuristic features
- Separate heuristic phishing risk engine (LOW / MEDIUM / HIGH)
- Streamlit web application with five sections
- No URL fetching, no HTML execution, no email storage

## 6. Requirements

### Functional
- Classify emails into three classes
- Provide phishing risk level and triggered indicators
- Display explanation for every analysis result
- Handle empty, malformed, and very long inputs

### Non-functional
- Deterministic preprocessing (same output every run)
- Input size limit: 100 KB per field
- Model loaded once at startup
- No user data stored

## 9. Preprocessing

Pipeline steps:
1. Coerce to string; handle None / NaN
2. Strip HTML using BeautifulSoup4 (text extraction only)
3. Normalize Unicode to ASCII
4. Lowercase conversion
5. Replace IP-based URLs with `ipaddresstoken`
6. Replace all URLs with `urltoken`
7. Replace email addresses with `emailtoken`
8. Remove punctuation except `!` and `?`
9. Normalize whitespace
10. Remove generic stop words (preserving security-relevant terms)

Security note: URLs are never visited or resolved.

## 11. TF-IDF Feature Extraction

- `TfidfVectorizer` from scikit-learn
- Word-level analyzer, unigrams + bigrams
- `max_features=5000–10000`, `min_df=2`, `sublinear_tf=True`
- Fitted **only** on training data to prevent data leakage
- Transformed test/inference data using the fitted vectorizer
- Saved as `models/tfidf_vectorizer.joblib`

## 12. Cybersecurity Feature Engineering

14 features extracted from raw (un-preprocessed) email:
url_count, has_ip_url, has_shortened_url, suspicious_url_score,
html_link_count, html_form_count, email_count, exclamation_count,
uppercase_ratio, urgency_score, credential_score, financial_score,
verification_score, subject_urgency

Feature order is fixed across training and inference.
All feature weights are HEURISTIC_DEFAULT values (not scientifically validated).

## 13. Model Training

Three candidate models:
1. **MultinomialNB** — fast, probabilistic, good baseline
2. **LogisticRegression** — balanced class weights, probability support
3. **LinearSVC (calibrated)** — often best for sparse text, CalibratedClassifierCV for probabilities

80/20 train/test stratified split, random_state=42.

## 14. Evaluation Methodology

- All metrics from held-out 20% test set only
- Metrics: Accuracy, Macro F1, Weighted F1, per-class Precision/Recall/F1
- Special focus: Phishing Recall (costs of missing phishing > costs of false alarm)
- Selection priority: Phishing Recall → Macro F1 → Accuracy
- Confusion matrix saved to reports/figures/

## 16. Phishing Risk Engine

Separate from ML classifier — does NOT influence the ML label.
Evaluates extracted features against a fixed indicator list.
Each triggered indicator adds a HEURISTIC_DEFAULT score weight.
Score → Risk Level: 0–19=LOW, 20–49=MEDIUM, 50+=HIGH.
Returns: risk_level, heuristic_score, triggered_indicators, explanation.

## 17. System Architecture

```
User Input → Preprocessing → TF-IDF + Security Features → ML Model
                                                         ↓
                                                   Phishing Risk Engine
                                                         ↓
                                        Result (label + risk + explanation)
```
